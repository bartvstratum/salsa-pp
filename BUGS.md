# Upstream bugs

Reproduced identically up to SALSA++ tag v0.1.0; fixed afterwards in both codes, one issue and commit each. `[x]` fixed (commit), `[ ]` open; n/a: not in the code we use.

- [ ] 1. `util.f90:1005` `calc_correlation` (UCLALES-SALSA): Σxy isn't summed, and an absolute `EPSILON` cut-off makes r = 0 for kg/kg masses. As a result, evaporated rain always goes to the a-bin, whatever its composition. The threshold is the epsilon of double since d1698a2 (24); the cross term is still open.
- [ ] 2. ~~`driver.f90:238` (old SALSA-standalone): rain number arrays are allocated with `ncld` instead of `nprc`. n/a: old standalone driver, not used.~~
- [ ] 3. ~~`driver.f90:425` (old SALSA-standalone): `output.dat` writes cloud data where rain should be. n/a: old standalone driver, not used.~~
- [ ] 4. ~~`driver.f90:211` (old SALSA-standalone): the NH3 gas slot gets the HNO3 value (no effect: master uses neither). n/a: old standalone driver, not used.~~
- [ ] 5. `mo_salsa_dynamics.f90:990` `gpparth2o` (UCLALES-SALSA): the explicit 0.02 s substeps of the aerosol water condensation (±10 % cap, Kelvin and mass transfer frozen per step) are too long for the smallest 2a/2b bins, so their wet size jitters from step to step. Gone with 0.002 s; S, cloud number and liquid water barely change.
- [ ] 6. `mo_salsa_dynamics.f90:1051` `gpparth2o` (UCLALES-SALSA): prints "CONDENSATION SUBSTEPING: SOMETHING'S WRONG" for every substep beyond 100, so on every call with dt > 2 s, per grid point.
- [x] 7. `mo_salsa_dynamics.f90:988` `gpparth2o` (UCLALES-SALSA): `DO WHILE (ttot < ptstep)` with a fixed adt = 0.02 s does one substep too many when the summed adt ends just below dt: in float at dt = 1, 2, 4 s (1.02 s of condensation per 1 s step), in double at dt = 5 s. Fixed in both codes (0aa27fc): `n = max(1, nint(dt/0.02))` substeps of `dt/n`.
- [ ] 8. `mo_salsa_dynamics.f90:773` `gpparth2o` (UCLALES-SALSA): aerosol water switches hard between equilibrium (RH < 98 %) and dynamic condensation (RH ≥ 98 %), so the wet sizes jump when RH crosses 98 % (case D at about 450 and 5550 s).
- [ ] 9. (https://github.com/bartvstratum/salsa-pp/issues/7) Dry mass is not conserved once rain forms (case D, up to +2e-4). Cause: precipitation formation in `coag_cloud` (`accumulatePrecipFormation`) gives rain the colliding volume explicitly, `(v_c n_b + v_b n_c) K dt fix_coag`, while the cloud bins lose it implicitly, `v dt S/(1 + dt S)`; `fix_coag` sums only part of the sink, so rain gets more than the cloud loses. Error per step ∝ dt² (1.7e-6 at dt = 1 s), so first order over a run; regular coagulation ~1e-10 per step. Fix option: each bin sends to rain what its own implicit sink takes for rain-forming pairs (no `fix_coag` for the volume); ~100-150 lines per code.
- [ ] 10. `mo_salsa_driver.f90:270` / `mo_salsa_properties.f90:188` `equilibration` (UCLALES-SALSA): the wet diameter is not reset per grid point (`updateDiameter` is commented out in `run_SALSA`), so the regime-1a equilibration (1 % tolerance) starts from the previous call's value, in an LES the previous grid point's. Results depend on the loop order.
- [ ] 11. `mo_submctl.f90:337` (UCLALES-SALSA): `nlim`/`prlim` are documented as # kg-1 and compared with # kg-1 in `SALSA_diagnostics`, but with # m-3 inside SALSA (`run_SALSA` converts the numbers). Check which is meant before fixing.
- [x] 12. `mo_salsa_properties.f90:148` `equilibration` (UCLALES-SALSA): the work array is filled for `cc = 1,5` only (SO4, OC, BC, DU, SS), so NO and NH never take up water in the equilibration, although the code has their terms. Fixed in both codes (0089fbc): `DO cc = 1,7`.
- [ ] 13. `mo_salsa_dynamics.f90:612` `condgas` (UCLALES-SALSA): with both organic vapours condensing in one call, the aerosol gets the non-volatile organic volume change twice (`zdvoloc` is added again in the semi-volatile part).
- [ ] 14. `mo_salsa_update.f90:132` `distr_update` (UCLALES-SALSA): `within_bins` is overwritten per bin instead of combined, and only bins that grew reach the check (the others `CYCLE` before it). Whether the loop repeats depends only on the smallest bin that grew; other bins can stay outside their limits.
- [ ] 15. `mo_salsa_update.f90:61` `distr_update` (UCLALES-SALSA): the aerosol loop starts at `fn2b-1`, so the largest 2b bin is never checked and never shrinks into the bin below.
- [ ] 16. `mo_salsa_update.f90:116` `distr_update` (UCLALES-SALSA): aerosol moves volume as `znfrac·N·zVexc·v/Σdry` (no cap), cloud and rain as `zvfrac·v` with `zvfrac` capped at 0.99; the aerosol `zvfrac` is computed but only used in the error check.
- [ ] 17. `mo_salsa_update.f90` `distr_update` (UCLALES-SALSA): `STOP` inside the per-point loop (no convergence after 100 iterations, negative fraction); for rain a negative fraction is printed as a warning first, then stops. In SALSA++ `Kokkos::abort`.
- [x] 18. `mo_salsa_properties.f90:305` `equilibration` (UCLALES-SALSA): the regime 2a/2b iteration (at initialisation, and in `gpparth2o` every call below RH 98 %) runs until the relative change of the wet diameter is below 1e-12, else `STOP` after 100 iterations. In float the rounding noise is far above 1e-12 (cancelling terms in the molality polynomials: a 2-cycle at 1.5e-5 at RH 0.97), so it stops. Fixed in both codes (64b0147): also end the iteration when the change no longer decreases (from the third iteration on). Never triggers in double (cases A-D identical); in float it ends after 3-7 iterations at a change of at most 1e-5.
- [x] 19. `mo_salsa_update.f90:86` `distr_update` (UCLALES-SALSA): aerosol and rain bins count as grown for `zvpart > pi6*dmid**3`, but the number fraction moved up is positive only for `zvpart > (vlolim + vhilim)/2`. Both are equal in exact arithmetic only (dmid is defined from the mean volume); a `zvpart` between them (window ~1e-6 relative in float, ~1e-15 in double) gives a slightly negative fraction and `STOP 'Error aerosol 0'` (rain: `Error, volc precp 0`). Initial aerosol sits exactly at the centre volume, so single precision stops at the first call. Fixed in both codes (64b0147): skip the bin when the fraction is < 0 (nothing has grown past the upper limit); identical in double where the Fortran does not stop.
- [x] 20. `constrain_SALSA.f90:443` `findDry4Wet` (UCLALES-SALSA): the parallel b bin of the chosen 2a bin is `bb = fn2a + (ba - in2a)`, which is the last 2a bin for `ba = in2a` and one bin short in 2b otherwise; meant is `in2b + (ba - in2a)`. Fixed in both codes (9917275): `bb = in2b + (ba - in2a)`; not reached by cases A-D.
- [ ] 21. `mo_submctl.f90:26-27` (UCLALES-SALSA): the comment of `lsauto` swaps the modes. The code forms rain through cloud-cloud coagulation with `lsauto%mode == 1` (`coag_cloud`) and calls the parameterised `autoconv2` with mode 2.
- [x] 22. `mo_salsa_cloud.f90` `actInterst` (UCLALES-SALSA): the number and wet volume profiles use dry particle volumes in m^3 (~1e-22 to 1e-16). In single precision the slope of the number density (~1e46) overflows and the cubes in `intgV` (~1e-60) underflow, giving NaN for the activated number and volume. Fixed in both codes (d1698a2): the volumes are scaled by 2^60, which is exact (double unchanged).
- [ ] 23. `constrain_SALSA.f90:29` `tend_constrain2` (UCLALES-SALSA): in single precision `-1. + 1.e-8` rounds to -1, so the limiter lets a step empty a field completely; and `MAX(limit, NaN)` (C++ `Kokkos::max`) returns the limit, so a NaN tendency silently empties the field instead of showing up. LES glue only (standalone driver); MicroHH will limit at `-fld_up/dt`.
- [x] 24. `mo_salsa_dynamics.f90:1155` `acth2o` (UCLALES-SALSA), and `calc_correlation` (driver stand-in, BUGS.md 1): machine epsilon used as an absolute threshold. In `acth2o` the floor of `znw + zns` (mol m-3) is 1.2e-7 in single precision, as large as the water of small droplets: the water activity drops to `znw/eps`, the droplets take up water at RH 0.95 instead of evaporating, and stay as cloud (case D: 1.1e6 kg-1 left at the end instead of 2). Fixed in both codes (d1698a2): the epsilon of double, so double is unchanged.
- [ ] 25. `mo_salsa_coagulation_processes.f90` `coag_cloud` (UCLALES-SALSA): pairs of equal size across the regimes (cloud a bin i, cloud b bin i) are counted twice as a sink: bin a_i loses to b_i through the regular sink to the other regime (`index_b..fcb`) and again through precipitation formation (`icb..index_b`), and the same the other way round. Also affects regular cloud-cloud coagulation without autoconversion.
